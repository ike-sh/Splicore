# Splicore v0.6.6

Release commit `{{COMMIT}}`. The exact Source Tree and build identity are
recorded in `RELEASE_MANIFEST.json`.

## Release overview

v0.6.6 is a reliability and storage-integrity release based on v0.6.5. It
contains the qualified DNS test-fixture repair, TrustTunnel HTTP/2 and HTTP/3
CONNECT cancellation fixes, and the P3 Commit Witness. It does not add a
protocol, change the API or protocol ABI, or advance SQLite schema 8.

The supported release targets remain Linux amd64 and Windows amd64. Both use
the single CGO-free native executable and the existing build tags. Formal
ARM64 support and release assets remain paused under `AMD64_ONLY`.

## DNS test-fixture repair

The protected-DNS fixture now owns a paired TCP/UDP port selection, performs
bounded retries on address collisions, closes sockets from failed selections,
and emits better diagnostic events. [PR #29](https://github.com/ike-sh/Splicore/pull/29)

This is a test-fixture repair, not evidence of a unique production DNS failure
cause. The original Windows protected-DNS fallback history in
[Issue #26](https://github.com/ike-sh/Splicore/issues/26) remains
`ROOT_CAUSE_UNRESOLVED`.

## TrustTunnel H2/H3 reliability

- HTTP/2 and HTTP/3 CONNECT now keep cancellation ownership with the operation.
- A cancelled stream is not returned to the caller.
- An in-flight cancellation callback is joined before the operation finishes.
- The HTTP/2 test peer has corrected lifecycle and shutdown ownership.

These changes passed the native Linux and Windows qualification gates and are
`TRUSTTUNNEL_H2_FIX_QUALIFIED`.
[PR #30](https://github.com/ike-sh/Splicore/pull/30) The historical run
[`44462452895`](https://github.com/ike-sh/Splicore/actions/runs/44462452895)
did not retain the underlying socket errno, so its original finding remains
`TRUSTTUNNEL_H2_ROOT_CAUSE_UNRESOLVED`.

## P3 Commit Witness

Schema 8 state now has an independently persisted Commit Witness beside the
SQLite database. Admission checks bind the installation, monotonic Revision,
canonical logical-state SHA256, and committed transaction identity. Business
state, Revision, and the committed journal transition are committed together;
the witness is then durably replaced before a successful mutation response is
returned. [PR #31](https://github.com/ike-sh/Splicore/pull/31)

Witness disagreement, damage, a pending witness, or an outcome-ambiguous commit
fails closed. Further mutations and managed binding admission are denied, and
the owning runtime is cancelled. Read-only integrity inspection uses a private
snapshot and does not initialize, migrate, recover, or modify the source state.

A new installation creates a native Revision-0 Witness before becoming
available. The qualified new-install lifecycle covers synthetic accounts,
credentials, bindings and inbounds, witness advancement after business
commits, clean shutdown, restart, integrity inspection and service recovery.
An existing Schema 8 database without a witness requires the documented,
explicit `state establish-witness --acknowledge-current-state` baseline after
the operator preserves a coherent database and Vault-key backup. That baseline
does not prove earlier acknowledgement history.

## Security and recovery boundary

The Witness qualifies acknowledged-loss detection and fail-closed admission;
it does not reconstruct lost committed-WAL content. Its record checksum is
consistency evidence, not authentication against a principal able to rewrite
both SQLite and the Witness. The database, WAL and Witness normally share one
disk and are not independent failure domains or substitutes for a separately
retained backup.

Committed-WAL reconstruction and common-disk disaster recovery are not
qualified. Physical power-cut testing and Windows production
`MaintenanceBackup` were not executed. Normal native restart/recovery and the
existing isolated storage fixtures remain qualified within their documented
scope.

## Known limits and open investigations

- The original amd64 Snell IPv6 Race finding remains
  `SNELL_V5_ROOT_CAUSE_UNRESOLVED`; [Issue #25](https://github.com/ike-sh/Splicore/issues/25)
  stays open and the qualified per-stream observer remains in place.
- The DNS fixture repair does not change the unresolved historical conclusion
  in Issue #26. The TrustTunnel cancellation fix likewise does not recreate the
  missing errno from its historical run.
- The upstream Mieru UDP receive-queue repair remains a verified result. Other
  historical reconnect findings retain their original conclusions unless a
  complete causal result exists.
- ShadowQUIC and Linux kernel WireGuard remain `ISOLATED_NOT_QUALIFIED`.
  Standard userspace WireGuard remains available. AmneziaWG/Phase37 is retired,
  and WAL/P1-B candidates remain outside production.
- Public NAT and path-MTU field trials, physical TUN/Wintun, Android/v2rayNG
  real-device interoperability and extended soak testing remain outside this
  release qualification.
