# Splicore v0.6.5

Release commit `{{COMMIT}}`. The exact Source Tree and build identity are
recorded in `RELEASE_MANIFEST.json`.

## Managed proxy servers

- **HTTP Proxy `http/1.1/base`** supports authenticated CONNECT and
  absolute-form forwarding. Ordinary HTTP processes one request per
  connection and sends `Connection: close`. The server uses managed accounts,
  scoped routing and encrypted SQLite recovery. [PR #24](https://github.com/ike-sh/Splicore/pull/24)
- **SOCKS5 `socks5/5/base`** supports RFC 1929 authentication and TCP CONNECT.
  Enable `settings.udp: true` for UDP ASSOCIATE with IPv4, IPv6 and domain
  targets. Each association owns a relay socket and uses the TCP peer IP and
  the explicit or learned UDP source port. UDP targets use protected Direct
  egress or Core Reject. The native client supports TCP and optional UDP.
  [TCP PR #23](https://github.com/ike-sh/Splicore/pull/23) · [UDP PR #27](https://github.com/ike-sh/Splicore/pull/27)
- UDP defaults to off. Client profiles export the configured UDP setting.
  Non-loopback deployments require an explicit cleartext opt-in. A remote UDP
  relay also needs an advertised address, an allowed UDP port range, and
  matching NAT forwarding when applicable. [SOCKS5 UDP configuration](https://github.com/ike-sh/Splicore/blob/v0.6.5/docs/CONFIGURATION.md#managed-socks5)

The Linux and Windows archives retain the single CGO-free executable and
encrypted SQLite schema 8. Existing TCP-only SOCKS5 settings remain valid.
[Operations and upgrade documentation](https://github.com/ike-sh/Splicore/tree/v0.6.5/docs)

The tests exercise independent HTTP curl, independent SOCKS5 wire clients,
two-Core TCP/UDP and UDP DNS traffic, binding isolation, credential changes,
socket ownership and SQLite restart. The workflows bind source, attempt and
runner evidence to the exact checkout. The Tag workflow assembles a Draft,
verifies all five downloads and runs both native smokes before publication.

## Known limits

- ARM64 is paused under `AMD64_ONLY`. The v0.6.4 release retains its historical
  assets and qualification record. [v0.6.4 history](https://github.com/ike-sh/Splicore/blob/v0.6.4/docs/releases/v0.6.4.md)
- SOCKS4, SOCKS5 BIND and UDP fragmentation reassembly are outside the managed
  SOCKS5 scope. The relay drops nonzero FRAG. A change to the UDP source port
  requires a new association. UDP payloads are best effort and RFC 1929 does
  not authenticate or encrypt each datagram.
- HTTP/2 proxy listeners, HTTPS proxy listeners, MASQUE and CONNECT-UDP are
  outside the managed HTTP profile. HTTP CONNECT can carry an HTTPS session.
- Public NAT and path MTU field trials, physical TUN/Wintun, and Android/v2rayNG
  real-device interop are `NOT_EXECUTED` within this release.
- The original amd64 Snell IPv6 Race and protected DNS fallback failures
  remain `ROOT_CAUSE_UNRESOLVED`. The Mieru reconnect and TrustTunnel Race
  histories also retain their original conclusions.
  [Original PR #24 run](https://github.com/ike-sh/Splicore/actions/runs/44863770485) ·
  [Snell #25](https://github.com/ike-sh/Splicore/issues/25) ·
  [DNS #26](https://github.com/ike-sh/Splicore/issues/26) ·
  [Historical Mieru run](https://github.com/ike-sh/Splicore/actions/runs/44800085002)
- ShadowQUIC and Linux kernel WireGuard remain `ISOLATED_NOT_QUALIFIED`.
  Standard userspace WireGuard remains available. AmneziaWG/Phase37 is retired.
  WAL/P1-B and unqualified restoration candidates remain excluded.
