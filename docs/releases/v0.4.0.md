# Splicore v0.4.0

The first downloadable release of the current Windows/Linux single-binary
foreground core. Release commit: `{{COMMIT}}`.

## Compatibility decision

This is **v0.4.0, not a v0.3.1 patch**. The current main line and v0.3.0 Phase36
Frozen have divergent capability/configuration histories. Frozen WireGuard
endpoints (including Linux kernel paths), ShadowQUIC, VLESS Encryption, XHTTP H3
and generic HTTP/H2/QUIC carriers are not restored. Do not treat this release as
a drop-in upgrade of a frozen deployment or mix their state/configuration trees.
The v0.3.0 tag and release remain unchanged. The project remains pre-1.0 and its
protocol profiles retain their documented experimental status.

## What is delivered

- One `splicore` / `splicore.exe` owns CLI, local control, native proxy listeners,
  encrypted vault, SQLite state and foreground daemon lifecycle.
- Offline help/version/check, explicit key provisioning, run/status/stop,
  real VLESS loopback traffic, authentication refusal, active-stream shutdown
  and persisted listener restoration on Windows/Linux amd64.
- No Xray, V2Ray, sing-box, Mihomo or other proxy-core process is bundled or
  required. Third-party Go libraries are embedded; CGO_ENABLED=0.
- Versioned archives contain the executable, license/attribution texts, complete
  third-party notices, minimal examples, platform instructions and inner hashes.
  A corresponding-source archive includes exact release sources and vendored
  dependencies, plus offline source-build instructions.

## Platforms and evidence

| Target | Build | Native qualification |
| --- | --- | --- |
| Windows amd64 | CGO0 PE | Default/full build, vet, tests; real packaged VLESS core |
| Linux amd64 | CGO0 ELF without interpreter/dynamic section | Default/full build, vet, tests; selected-package Race; real packaged VLESS core |
| Windows arm64 | CGO0 cross-compile | BUILD ONLY; native tests NOT EXECUTED |
| Linux arm64 | CGO0 cross-compile | BUILD ONLY; native tests NOT EXECUTED |

The Release Manifest records source identity, build settings, hashes and actual
test outcomes. Native process tests transfer/verify 32 KiB per startup, reject a
wrong UUID, stop with an active stream, wait for exit 0, check port release and
restart from SQLite. Linux tests SIGINT and stop; Windows tests stop. Published
downloads are checksum-verified and exercised on native Windows/Linux amd64.

## Download and run

Select the archive for your OS/architecture, download SHA256SUMS, verify the
archive, then unpack and follow RUNNING.md. `help` and `version --json` run
directly. To start a fresh core, provision its private key, customize the
absolute bootstrap paths, run `check`, then `run`. A fresh state has no proxy
listener until an inbound is explicitly applied. See the included loopback
example. Keep state/key directories private and preserve the original key.

Linux: `sha256sum -c SHA256SUMS`. Windows:
`Get-FileHash -Algorithm SHA256 ./splicore-v0.4.0-windows-amd64.zip`.
SHA256 is supplied; no digital signature is claimed. Source and build materials
are in the source archive and the exact tag. No old release assets are replaced.

## Known limits retained

- Windows Race NOT EXECUTED. Local Windows file-symlink fixture can be SKIP on
  Win32 1314; hosted qualification requires it and does not allow that exception.
- ARM64 is cross-build only. VLESS loopback qualification does not certify every
  implemented protocol/security/transport combination or official peer interop.
- Implemented experimental modules include VMess, Shadowsocks/SS2022, Hysteria2,
  Mieru, REALITY, XHTTP H1/H2, Naive H2/H3, modern mKCP and others in the capability
  matrix. They do not gain broad release interoperability/throughput certification
  from the VLESS process test. Hysteria v1 and XHTTP H3 are unsupported.
- WSL2 large-UDP/timeout history, historical SOCKS UDP diagnostic gaps and Mieru
  large-transfer performance remain unqualified; no blanket fix is claimed.
- SQLite current-main behavior is retained. Independent WAL/P1-B candidates are
  excluded; these tests are not crash/power-loss/data-loss certification.
- Windows WireGuard Hotfix remains NOT QUALIFIED. Phase37 WIP remains isolated.
- Windows service installation/production backup, TUN, host networking and real
  hardware qualification remain limited. Optional Windows TUN needs external
  Wintun DLL/driver and privileges; Linux TUN and UDP-range nft rules also require
  OS facilities/privileges. System drivers are not embedded.
- Linux Race instruments selected in-process tests, not the CGO0 product child.
  Windows console Ctrl+C / separate SIGTERM injection were not tested.
- `check` validates server projections/resources and stored client/network graph;
  it is not full client factory/credential precompilation or a port reservation.
  `stop` success acknowledges the request; completion is verified separately.
