# Splicore v0.6.7

Release commit `{{COMMIT}}`. The exact Source Tree and build identity are
recorded in `RELEASE_MANIFEST.json`.

## Release overview

v0.6.7 is a lifecycle-reliability and qualification release based on v0.6.6.
Its production change is limited to the Naive HTTP/2 and HTTP/3 stream,
connection-pool, and asynchronous cleanup lifecycle. It also includes five
qualified test-fixture or evidence improvements for Naive H3, Hysteria,
Snell v5, Phase20, and Hysteria2.

This release does not add a production protocol, dependency, configuration or
CLI surface; change a wire format, Protocol ABI, API version, Config Schema 1,
or SQLite Schema 8; or require a user-data migration. The supported release
targets remain Linux amd64 and Windows amd64. Formal ARM64 support, CI gates,
and release assets remain frozen under `AMD64_ONLY`.

The release remains `READY_WITH_LIMITATIONS`. A successful current candidate
does not resolve the historical incidents and storage-integrity risks listed
below.

## Naive H2/H3 lifecycle reliability

[PR #34](https://github.com/ike-sh/Splicore/pull/34) makes Naive stream closure
and cleanup ownership explicit without changing payload framing, the handshake,
the protocol version, or dependencies:

- `CloseWrite` has a linearized terminal-state contract and remains independent
  of concurrent carrier writes and the read half of the stream. It commits a
  local send-half completion; it does not guarantee remote delivery.
- HTTP/2 half-close no longer depends on the carrier-wide write lock, while
  committed carrier failures still remain terminal.
- HTTP/3 distinguishes a completed local FIN from reset or connection-terminal
  failure; full Close preserves an already completed send half and cancels an
  unfinished one.
- Padded writes preserve the same terminal close/error contract.
- Full stream Close publishes local terminal state and returns capacity exactly
  once without joining an unrelated blocked transport writer.
- One tracked asynchronous owner closes the response body and joins the read
  pump; Client shutdown closes carriers first and joins Open, stream-cleanup,
  timer, and physical-close ownership.
- Connection-pool liveness checks occur outside the pool mutex and revalidate
  slot, connection, generation, and retirement identity before committing.
  Idle callbacks and timers have explicit generation and shutdown ownership.

The native Linux and Windows Default, Full, and Race gates retain H2/H3
half-close, full-close, padding, carrier-failure, pool-capacity, timer,
reconnect, and shutdown regressions. These changes do not establish that every
historical Naive failure had the same cause. The historical Naive H3 incident
remains `NAIVE_H3_ROOT_CAUSE_UNRESOLVED`.

## Qualification and test-fixture reliability

These changes strengthen test ownership and failure evidence. They are not
production protocol performance or transport changes:

| PR | Qualified change | Preserved historical boundary |
| --- | --- | --- |
| [#33](https://github.com/ike-sh/Splicore/pull/33) | Keep the Naive H3 test carrier alive until target-worker join and require deterministic abort cleanup. | Test fixture only; historical Naive H3 root cause remains unresolved. |
| [#35](https://github.com/ike-sh/Splicore/pull/35) | Isolate each Hysteria LivePool fixture peer's ingress and reverse-path ownership. | Test fixture only; no production Hysteria transport claim. |
| [#36](https://github.com/ike-sh/Splicore/pull/36) | Retain Snell v5 fixture endpoints through the official-peer lifetime and prove cleanup/rebind. | Test fixture only; Issue #25 stays open and the historical root cause remains unresolved. |
| [#37](https://github.com/ike-sh/Splicore/pull/37) | Preserve bounded structured Phase20 lifecycle evidence in a dedicated projection while keeping general/failure output redacted. | Evidence/test change only; no historical residue owner was identified. |
| [#38](https://github.com/ike-sh/Splicore/pull/38) | Join Hysteria2 parallel-fixture workers and the UDP collector on abnormal pre-start or in-flight cleanup. | Test fixture only; no production Hysteria2 UDP, fragmentation, packet-loss, or performance claim. |

The #38 change preserves the original two users, 8 TCP and 2 UDP flows per
user, payload sizes, 15-second Deadline placement, 10-second admission bound,
concurrent start, accounting, credential-isolation, and final Active assertions.
It qualifies the fixture cleanup repair, not the historical normal-start UDP
timeout.

## Compatibility and migration

The v0.6.6 to v0.6.7 source range has:

- no `go.mod` or `go.sum` change and no new production runtime dependency;
- no Config Schema, SQLite schema, API version, Protocol ABI, OpenAPI, CLI, or
  configuration-format change;
- no protocol framing, handshake, or wire-format change;
- no new production protocol or runtime Core dependency;
- no user-data migration requirement.

Existing v0.6.6 configuration and Schema 8 state remain the compatibility
baseline. Preserve the original master key with the database and follow the
stopped-process backup/upgrade procedure. Xray, V2Ray, Mihomo, and sing-box
remain optional independent test or client peers, not Splicore production
runtime dependencies.

## Storage integrity and backup boundary

The P3 Commit Witness continues to qualify detection of state/witness
disagreement and fail-closed admission. It does not reconstruct lost
acknowledged rows or committed-WAL content. Its checksum is consistency
evidence, not authentication against a principal able to rewrite both SQLite
and the Witness. The database, WAL, and Witness normally share one disk and are
not independent failure domains or substitutes for an independently retained
backup.

The historical Phase15 backup-crash/source-preservation failure remains
`PHASE15_BACKUP_CRASH_FAILURE_ROOT_CAUSE_UNRESOLVED`. Later passing runs do not
exclude a production data-integrity defect. Physical power-cut recovery and
Windows `MaintenanceBackup` remain outside qualification. Windows foreground
operation has no production `state backup` command; use the documented stopped-
process manual generation-copy procedure rather than treating this limit as an
absence of every backup path.
