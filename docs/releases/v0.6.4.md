# Splicore v0.6.4

Release commit `{{COMMIT}}`.

This release covers the changes since the latest preceding published version,
v0.6.2. v0.6.3 remains an `UNPUBLISHED_CANDIDATE_TAG`.

## Production fixes

- **TUIC authentication stream shutdown.** A valid authentication command can
  finish sending FIN before the server cancels reads on its command stream.
  Authentication still completes before FIN, so parallel CONNECT can proceed.
  The existing read deadline bounds a sender that leaves the stream open.
  Regression coverage includes IPv4 and IPv6 loopback. [Splicore PR #15](https://github.com/ike-sh/Splicore/pull/15)
- **Mieru UDP receive progress.** The SDK handles new-session admission when
  accept queues fill so the shared UDP receive loop can continue processing
  DATA, ACK, and Close for established sessions. The patch also corrects the
  UDP read-deadline wakeup order and keeps the socket available for session
  cleanup during Mux cancellation. [Splicore PR #16](https://github.com/ike-sh/Splicore/pull/16)
- **Mieru source.** Go keeps the `github.com/enfein/mieru/v3 v3.39.0` module
  identity and resolves it to the internal Fork
  `github.com/ike-sh/mieru/v3 v3.0.0-20261118111519-f237626f5345`.
  The fixed Fork commit is `f237626f5345d83ba35d8e24c1721dc8e1c928d3`.
  Its source and license are included in the corresponding source archive.
  [Fork commit](https://github.com/ike-sh/mieru/commit/f237626f5345d83ba35d8e24c1721dc8e1c928d3) ·
  [Upstream PR #335](https://github.com/enfein/mieru/pull/335)

## Compatibility and diagnostics

The release retains Splicore's independent single-binary architecture, existing
configuration formats, and encrypted SQLite schema 8. Standard WireGuard
continues to use its qualified userspace backend. Xray and the official Snell
binary are independent test peers.

P2 adds native network measurements and isolated network-condition fixtures.
The CI measurements establish a baseline without a performance SLO. P3 adds
separate native platform qualification and bounded disk-backed persistence
diagnostics for process exit, transaction and WAL boundaries, and backup
restore. These diagnostics leave production storage and recovery unchanged.
They preserve the known write-admission blind spots after WAL damage and the
existing limits on recovery of acknowledged data.

## Test fixture fixes

- The WireGuard Xray fixture leases OS-assigned ports and checks that the
  child actually owns its listening sockets. The original ARM64 Race failure
  recorded a collision at UDP port 33434. The historical port owner remains
  `ORIGINAL_PORT_OWNER_UNKNOWN`. [Original ARM64 job](https://github.com/ike-sh/Splicore/actions/runs/44491750040/job/135448841149)
- The Gecko reassembly test uses `testing/synctest` so the background sweeper
  cannot expire its synthetic fragments on the runner's wall clock. Its
  malformed input, expiry, conflict, capacity, 512-message wraparound and
  shutdown checks remain in place.

## Qualification scope

Release archives use Go 1.26.3, `CGO_ENABLED=0`, and
`with_quic,with_utls,with_gvisor`. The official workflow records two native
amd64 targets and two ARM64 cross-builds. Independent native platform CI
records its results separately from the release archives.

| Platform | Official archive qualification | Independent native CI |
| --- | --- | --- |
| Linux amd64 | Default/full builds, vet, tests, full release Linux Race, and downloaded-product traffic and restart | Core runtime qualification |
| Windows amd64 | Default/full builds, vet, tests, typed Winsock UDP receive recovery, and downloaded-product traffic and restart | Native Windows amd64 Race with process lifecycle and persistence |
| Linux ARM64 | `BUILD_ONLY` | Native default/full builds, vet, tests, lifecycle, persistence, available peer tests, and Race |
| Windows ARM64 | `BUILD_ONLY` | Native default/full builds, vet, tests, lifecycle, persistence, and available peer tests. Race is `NOT_EXECUTED`. |

Native gates cover independent pinned protocol peers, authentication and
negative cases, connection and socket cleanup, and restart of the actual
program. `RELEASE_MANIFEST.json` records the exact source and the release
workflow's executed and skipped behaviors. The ARM64 rows and Windows Race in
that manifest describe the release workflow. The separate native runs provide
the additional evidence listed above. Official Snell peer coverage is scoped
to Linux amd64, with other platform coverage enumerated by the qualification
policy.

## Known limits

- The v0.6.3 Tag workflow failed the Gecko fixture and the official Snell v5
  concurrent QUIC test with an IPv6 target. The Gecko test-clock issue is
  addressed here. The historical Snell read timeout remains
  `ROOT_CAUSE_UNRESOLVED`. The official v5.0.1 peer, its pinned digest, and
  the full concurrent test remain part of Linux amd64 qualification.
  [Original v0.6.3 Tag run](https://github.com/ike-sh/Splicore/actions/runs/44511422648)

- TrustTunnel historically failed `TestH2InitialWindowOnWire` under Linux Race
  after PR #16. Its original `tcp_connect` failure remains
  `ROOT_CAUSE_UNRESOLVED`. Local paired evidence showed an identical test
  binary and reproduced the HTTP/2 close-before-deadline-reset order on both
  trees. The result of this release's Race gate applies to this run.
  [Historical CI run](https://github.com/ike-sh/Splicore/actions/runs/44462452895)
- ShadowQUIC and the Linux kernel WireGuard backend remain
  `ISOLATED_NOT_QUALIFIED`. AmneziaWG/Phase37 is `RETIRED`.
- WAL/P1-B, automated media-corruption recovery, and the historical Admission
  Guard candidate remain outside production qualification. The bounded process
  failure diagnostics leave OS crash and physical power-loss recovery
  `NOT_EXECUTED`.
- Physical TUN/Wintun, Android/v2rayNG devices, and optional historical client
  or long-soak campaigns retain their existing limits. The native peer records
  enumerate unavailable clients and skipped platform cases. Windows production
  backup remains outside the Linux maintenance qualification.
- The Mieru patch covers the validated input progress and socket lifecycle
  behavior. Historical reconnect EOF, UDP response truncation, and c100
  handshake investigations remain open. The `Server.Stop` retained object
  graph remains `LIFETIME_CONTRACT_UNDEFINED`.
