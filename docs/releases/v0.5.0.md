# Splicore v0.5.0

Based on v0.4.0, this release restores **native VLESS Encryption** to the
Windows/Linux single-binary mainline. Release commit: `{{COMMIT}}`.
PR [#6](https://github.com/ike-sh/Splicore/pull/6) was merged with commit
`1c9bd603d88e715f80779f556a3f34c657dd37f7`.
The v0.3.0 and v0.4.0 tags and historical Releases remain unchanged.

## Encryption and configuration

- Every full encrypted handshake combines ephemeral ML-KEM-768 and X25519.
  Static authentication keys can be X25519 or ML-KEM-768; bounded ordered key
  chains are supported. Records use AES-GCM or ChaCha20-Poly1305.
- Supported modes: `native`, `xorpub`, `random`; client policies: `1rtt`, `0rtt`.
  Ticket state is bounded and rejects replay; expiration/restart can require a
  fresh connection. Failed application data is never automatically replayed.
- `splicore vlessenc --auth mlkem768 --mode random --handshake 0rtt --ticket 600s`
  explicitly outputs private server `decryption` and public client `encryption`
  strings. Store generator output privately. Set inbound
  `server_secret.decryption`; client nodes use `options.data.encryption`.
  The server key stays in the existing encrypted credential vault, while public
  settings/profiles contain only the derived client projection. Schema remains 8.
- Raw TCP supports outer `none`, verified TLS, or REALITY, with flow-none or
  TCP-only Vision. Existing shared carriers retain their own restrictions.
  UUID authentication remains mandatory inside the encrypted channel.
- Explicit malformed/null/empty encryption options, wrong keys, altered
  records, replay and invalid credentials fail closed. Omitted historical
  encryption fields retain plain VLESS semantics.
- Encrypted foreign export is limited to the tested Xray `26.10.21` JSON target.
  Other versions/formats and unrepresentable mask intent reject instead of
  silently removing encryption. Android/v2rayNG import is not certified.

Sudoku/FinalMask is a separate obfuscation layer and never substitutes for
VLESS Encryption. The implementation remains native; no Xray process or
executable is bundled, linked or required by the production core. Official Xray
is used only as an independent test peer.
See [configuration and protocol limits](https://github.com/ike-sh/Splicore/blob/v0.5.0/docs/protocol/VLESS_ENCRYPTION.md).

## Verified release scope

| Target | Build | Native qualification |
| --- | --- | --- |
| Linux amd64 | CGO0 ELF, no interpreter/dynamic section | Default/full build, vet, tests; Linux race; real packaged/downloaded process |
| Windows amd64 | CGO0 PE | Default/full build, vet, tests; real packaged/downloaded process |
| Linux arm64 | CGO0 cross-build | BUILD ONLY; native execution NOT EXECUTED |
| Windows arm64 | CGO0 cross-build | BUILD ONLY; native execution NOT EXECUTED |

The tag workflow rebuilds from the exact latest main release commit and requires
the pinned official Xray-core **v26.10.21 / 1b1647c** test peer. On both native
platforms, the 48-cell wire matrix covers both directions, three modes, two
static authentication methods, both record ciphers, 1-RTT/0-RTT and resumption.
The 36-cell production runtime/export matrix covers both directions, outer
none/TLS/REALITY, flow-none/Vision and all three modes using real network traffic.
Negative tests cover wrong keys/UUIDs, malformed/tampered records, replay,
expiration/cache limits, cancellation and resource ownership.

Real core processes transfer and verify 32 KiB for plain, Sudoku, encrypted and
encrypted+Sudoku profiles; refuse wrong UUIDs; stop with a live stream; release
listeners; and restore credentials/listeners from SQLite after restart. CLI,
key generation, strict configuration and supported/rejected export behavior are
tested. Native carrier composition tests include TCP/XUDP over the existing
WebSocket, HTTPUpgrade, gRPC, XHTTP and modern mKCP paths; independent reference
runtime claims above are for raw TCP.

The Release Manifest records exact source/build identities, hashes and test
outcomes. Hosted native qualification forbids skipped tests, including symlink
security cases. This scoped evidence does not certify every protocol, transport,
client, public network, or hardware combination.

## Downloads and use

Choose the matching OS/architecture archive and download `SHA256SUMS` and
`RELEASE_MANIFEST.json`. Verify SHA256 before unpacking; follow included
`RUNNING.md`. Each platform archive contains one executable, licenses/notices,
examples, build metadata and inner checksums. The corresponding-source archive
contains exact sources, vendored dependencies and offline build instructions.
No digital signature is claimed. Public published downloads are hash-checked
and run again on native Windows/Linux amd64.

Existing v0.4.0 plain configurations retain their omitted-encryption semantics.
Back up the database together with its original vault key before upgrading.
Enabled encrypted configuration requires a build that implements this feature;
do not mix Frozen and current state/configuration trees.

## Known limits and remaining convergence

- Android/v2rayNG real-device import, VPN startup and traffic: **NOT EXECUTED**;
  no attached Android device was available. No Android interoperability claim.
- Windows Race: **NOT EXECUTED**, no configured native C toolchain. Local Windows
  symlink fixtures can lack privilege (Win32 1314); hosted release qualification
  requires them to pass and permits no skip. Console Ctrl+C/SIGTERM injection
  remains outside Windows process qualification.
- Both ARM64 targets remain **BUILD ONLY**. TUN, Windows services/production
  backup, broad host networking/hardware, WSL2 large UDP and historical
  SOCKS/Mieru performance retain their documented qualification limits.
- Frozen XHTTP H3, generic HTTP/H2/QUIC carriers, ShadowQUIC, WireGuard native
  endpoints/kernel paths, full Snell v4/v5 DRS/QUIC restoration, managed server
  DNS/route additions and other tracked historical gaps are still pending.
  This release is partial historical feature convergence.
- Windows WireGuard Hotfix remains **NOT QUALIFIED**. Phase37 WIP and independent
  SQLite WAL/P1-B candidates are excluded. No crash/power-loss certification.
- All protocol profiles remain experimental. Subsequent restorations use one
  short-lived PR at a time from latest main. Local hooks are auxiliary and do
  not replace GitHub protection; no server ruleset is changed by this release.
