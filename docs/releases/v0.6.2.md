# Splicore v0.6.2

This release delivers a qualified subset on the v0.5.0 native single-binary mainline.
The immutable v0.6.0 and v0.6.1 candidate tags remain unpublished and unchanged.
v0.6.0 failed ShadowQUIC qualification; v0.6.1 publication was held after its
post-merge lifecycle campaign failed an immediate ephemeral UDP port rebind.
v0.6.2 is the next unused patch tag. Release commit:
`{{COMMIT}}`. Existing v0.3.0, v0.4.0 and v0.5.0 tags, Releases and evidence are
preserved. The complete 61-entry historical inventory is versioned in
`distribution/historical-features.json`.

## Restored scope

- XHTTP HTTP/3, including ALPN/configuration, bounded connection reuse, request
  body ownership and safe retry boundaries. Native VLESS, VMess and Trojan H3
  traffic is tested against digest-pinned official Xray v26.10.21. Encryption
  and Vision combinations keep their explicit profile restrictions.
- Generic HTTP/H2 and QUIC stream carriers, strict configuration/export rules,
  independent standard-library/QUIC peer traffic and bounded shutdown.
- Standard WireGuard endpoints, API/CLI/bootstrap wiring, Core routing/DNS,
  userspace IPv4/IPv6, PSK, AllowedIPs, roaming/replay rejection and lifecycle.
  Native Windows/Linux use a separate process built from pinned official
  wireguard-go engine/netstack; Xray supplies an additional independent peer.
  Both native platforms deliver the userspace backend. The restored Linux kernel
  backend is isolated after repeated hosted concurrent fresh IPv6 UDP failure;
  explicit kernel activation returns KERNEL_NOT_QUALIFIED. Auto selects userspace
  and reports that availability reason. No kernel fast-path qualification is claimed.
- Snell v4, v5 DRS/QUIC support and shared listener ownership. Official Snell
  v5.0.1 interoperability is Linux-only; Windows uses native protocol tests.
- Managed server target routing/DNS, native TUN outbound dialing, timestamp
  monotonicity and historical regression coverage. Mieru v3.39.0 includes the
  restored read-deadline/ownership adaptation.

VLESS Encryption remains native: hybrid ML-KEM-768/X25519, AES-GCM or
ChaCha20-Poly1305 records, native/xorpub/random modes, bounded 1-RTT/0-RTT state,
UUID authentication and replay rejection. Sudoku/FinalMask is a separate layer.
No external Xray, sing-box or Mihomo executable is linked, bundled or launched.

## Corrections and qualification

Windows WireGuard now discards only a consumed, oversized UDP datagram reported
as typed WSAEMSGSIZE and continues on the same Socket/Device/receive worker.
All other errors retain their original semantics. Native regression records
real Winsock error 10040, truncated byte counts, subsequent authenticated traffic,
IPv4/IPv6 loopback and available NIC addresses, repeated injection and cleanup.
This release's acceptance is fresh; older Hotfix campaign reports keep their
historical NOT QUALIFIED conclusions.

H3 idle fixtures
expire the real stream timer without racing pending padding activity. External
test peers use leased ports outside ephemeral client port ranges, retain startup
errors, share one process-wait owner and write portable evidence paths.
Shadowsocks fixtures lease and probe TCP and UDP together for the server's shared
port, rather than treating a TCP-only ephemeral port as UDP availability evidence.
The Linux Shadowsocks abuse fixture also observes its actual UDP receive queue
draining between the malformed-input and authenticated-recovery phases. A
controlled kernel-overflow experiment confirms that a single recovery datagram
can be dropped before decoding while the flood queue is full; the earlier hosted
timeout did not record enough queue state to establish its exact cause. Flood
counts, association/resource limits, single-send payloads and the original
three-second per-packet deadlines remain unchanged. A receiver that exits or
does not drain still fails qualification.
Host recovery validates binary Windows SID/ACE identities with the same strict owner,
SYSTEM/user-only principals and full-access rights, independent of SDDL aliases.
UDP route tests wait for the relay's explicit post-write counter observation.
The HTTP churn fixture observes the original resource limits within its existing
three-second cleanup deadline, allowing closed net/http and origin workers to
finish; lingering workers still fail and retain their full goroutine stacks.
These changes preserve payload,
negative security, half-close and resource-release assertions.

UDP session cancellation now joins its in-flight socket-close callback before
retiring the session, using the existing owned-flow close mechanism. Concurrent
Close calls can return for a later caller while the first caller still finishes
OS-handle cleanup. A deterministic blocked-close regression verifies that the
callback completes before retirement. The original ten-cycle traffic, half-close,
immediate UDP rebind and resource-count assertions remain byte-for-byte intact,
with the same shutdown deadlines. Both cases are required on native default/full
profiles and complete Linux Race. No port retry is used to admit this fix.

Native release CI executes default/full builds, vet and tests, full Linux Race,
required behavior identities and real Core traffic/authentication/stop/restart.
Independent peer digests and outcomes are retained. Optional historical external
oracles and hardware campaigns are listed individually in the manifest as
NOT EXECUTED; an unexpected skip or a skipped required safety test rejects the
release. Hosted Windows must execute the UDP/443 and real symlink checks.

## Compatibility and exclusions

Existing v0.5.0 bootstrap/configuration and encrypted SQLite schema 8 are retained.
New endpoint/transport options are explicit; older cores can reject them and
must not silently downgrade them. Back up state together with its original vault
key. Frozen configurations and databases are not interchangeable with main.

ShadowQUIC restoration is ISOLATED_NOT_QUALIFIED: the formal v0.6.0 Linux
official-client/native-server restart and reconnect campaign timed out. Local
targeted passes do not replace the failed campaign. Its complete source and
tests are preserved in a verified recovery bundle and immutable v0.6.0 tag;
all added implementation, registrations, API schemas and protocol-specific
dependencies are excluded from this release. No ShadowQUIC support is claimed.

The isolated Linux kernel WireGuard source and tests are also preserved in the
same verified immutable candidate archive. Its original 100 sequential plus
20 concurrent lifecycle test failed a fresh IPv6 UDP exchange in two hosted
full-suite campaigns. The exact cause remains unestablished; local diagnostic
passes do not qualify that backend. The standard userspace implementation,
independent-peer traffic and Windows typed receive correction remain separate.
Shared DNS ordering, fallback error and rollback assertions are retained.

AmneziaWG/Phase37 AWG is intentionally retired and is not restored or advertised.
Standard WireGuard is separate. SQLite WAL/P1-B candidates and unrelated
historical architecture work are excluded and archived; this is not crash or
power-loss certification. Historical optional client/hardware combinations that
were not executed do not acquire certification through this release.
