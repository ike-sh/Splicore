# Native AnyTLS

Splicore implements AnyTLS inbound and outbound in the native Core. The stack is
application request → AnyTLS stream → AnyTLS session → TLS → TCP. The runtime
does not execute or embed anytls-go or sing-box. The implementation follows the
[published AnyTLS protocol](https://github.com/anytls/anytls-go/blob/v0.0.13/docs/protocol.md)
and [UoT2 format](https://sing-box.sagernet.org/configuration/shared/udp-over-tcp/).

The canonical protocol key is `anytls / 2 / base`. Version 2 is the default.
Version 1 peers retain TCP, UDP-over-TCP, padding and session reuse; SYNACK and
heartbeats activate only after version negotiation permits them. A client without
server settings initially treats its peer as version 1. Its first open allows
100 ms for negotiation; a negotiated v2 open waits at most 5 seconds for SYNACK.

## Server

Use the managed creation API with protocol `anytls`. Save the following creation
document in an owner-only file, replace the endpoint and TLS material, then use
`splicore inbound validate --protocol anytls --file /private/anytls.json`.
For a running Core, `inbound plan` and `inbound apply` use the same `--protocol`,
`--config`, `--file` and saved `--plan` contract. The HTTP endpoints are
`POST /api/v1/creation/anytls/validate`, `/plan` and `/apply`; apply accepts
`document`, `digest` and `revision` from the corresponding plan. For example:

```json
{
  "schema": 1,
  "name": "AnyTLS server",
  "listener": {"host": "127.0.0.1", "port": 8443},
  "display_endpoint": {"host": "proxy.example", "port": 8443},
  "settings": {
    "tls": {
      "server_name": "proxy.example",
      "certificate_file": "/etc/splicore/cert.pem",
      "private_key_file": "/etc/splicore/key.pem",
      "ca_certificate": "<one PEM CA certificate>"
    },
    "version": 2,
    "max_sessions": 512,
    "max_streams": 128
  },
  "users": [
    {"account_name": "Alice"},
    {"account_name": "Bob", "password": "replace-with-a-strong-password"}
  ]
}
```

Omitted passwords are generated by the shared credential service. The managed
model retains separate Account, Credential and Binding records. At most 16 users
are accepted, with unique password identities. Account eligibility and enabled
bindings determine the runtime snapshot. User changes restart the affected
generation; they are not hot session mutations. Counters identify the binding
and count authenticated TCP/UDP payload and logical streams in that generation.
Quota and speed enforcement are unsupported; metadata-only policy is explicit.

TLS is mandatory. Shared TLS validation snapshots the certificate and protected
private key. Handshake/authentication and initial destination reads have bounded
5-second deadlines. There is no plaintext or authentication fallback. Optional
`alpn` is an array of unique protocol names; its default is empty.

## Client

Create a canonical remote node using protocol `anytls / 2 / base`, a TCP
transport, TLS security, the remote endpoint and a separately owned password
credential. Node `security.tls` uses the shared contract:

```json
{
  "enabled": true,
  "server_name": "proxy.example",
  "trust": "system"
}
```

For a custom CA, use `trust: "explicit_ca"` and `ca_certificate` containing one
PEM CA certificate. DNS SNI, hostname checking and certificate validation are
enabled normally. IP server names use the standard Go TLS behavior, which omits
IP literals from the SNI extension. The AnyTLS-specific `options.insecure` is
false by default. Explicit `true` skips certificate validation and cannot be
combined with an explicit CA. It does not disable TLS encryption.

Client `options` fields:

| Field | Default | Accepted values / meaning |
| --- | --- | --- |
| `udp` | `true` | Enable UoT2 packet sessions |
| `version` | `2` | `1` or `2` |
| `idle_session_check_interval` | `"30s"` | 1 ms–1 hour |
| `idle_session_timeout` | `"30s"` | 1 ms–24 hours |
| `min_idle_session` | `0` | Preserve up to this many existing idle sessions |
| `max_sessions` | `128` | 1–128, includes pending session creation |
| `multiplex_streams` | `1` | 1–128; values above 1 allow active session reuse |
| `client_metadata` | `""` | Empty, `splicore`, or `splicore/...`; at most 128 bytes |
| `insecure` | `false` | Explicit certificate validation bypass |
| `uot_mode` | `"non_connect"` | `connect` or `non_connect` |

The default pool chooses the newest idle session, and creates a session when all
are busy. Optional active multiplexing uses bounded streams on the same session.
Sequence numbers and stream IDs increase monotonically; exhaustion fails safely
before wraparound. Idle cleanup keeps the newest `min_idle_session` existing
sessions and never expires an active stream. It does not prewarm sessions.

## Commands and padding

Authentication sends SHA-256(password), a big-endian 16-bit padding length and
the complete padding. Session frames encode command, big-endian 32-bit stream ID,
big-endian 16-bit length and payload. Settings precede SYN. SYNACK acknowledges
the destination connect result; a failure closes its stream. FIN closes the full
logical stream, with buffered received bytes available to the reader. AnyTLS
does not provide TCP half-close. Stream close leaves a healthy session reusable.
Session shutdown releases all owned workers without sending stream FIN replies.

The client sends heartbeats after 30 seconds without activity on a negotiated v2
session. A missing response closes it after 10 seconds. Both roles answer
heartbeat requests. Alerts close the session; logs retain the event and payload
size without printing untrusted peer text or credentials.

Server `padding_scheme` is a newline-delimited string. Its default is:

```text
stop=8
0=30-30
1=100-400
2=400-500,c,500-1000,c,500-1000,c,500-1000,c,500-1000,c,500-1000
3=9-9,500-1000
4=500-1000
5=500-1000
6=500-1000
7=500-1000
```

`stop=N` processes indices below N. Index 0 pads authentication; later rules
split and/or pad one submitted TLS plaintext write. The `c` marker stops further
padding once the previous fragment consumed the user data. Missing rules pass
data through. Settings, SYN and initial proxy bytes share the first session
write. Fragmentation does not advance the logical counter. Random range choices
use cryptographic randomness. A gap smaller than the 7-byte frame header remains
unpadded because it cannot contain a complete Waste frame.

The parser bounds scheme size to 8192 bytes, packet indices to 0–63, at most 32
steps per rule and at most 1 MiB total requested size per rule. Malformed,
duplicate, negative and overflowing values fail validation. The protocol's MD5
identifies the exact scheme text; it is not used for authentication. A mismatch
causes the server to send a validated update. The client saves it per remote
client pool for future sessions; existing session policies remain immutable.

## TCP and UDP

TCP targets use the shared SOCKS address codec: IPv4, IPv6 and domain addresses.
UDP uses the reserved `sp.v2.udp-over-tcp.arpa` target and UoT version 2. Both
connected and nonconnected framing are supported. The UoT request accompanies the
initial proxy data, allowing servers that read it before SYNACK to proceed.
Nonconnected datagrams preserve destination addresses and ports.

UDP is carried over an ordered TCP stream, so it inherits TCP retransmission and
head-of-line delay. Zero-length datagrams are preserved. The framing permits
65535 bytes; actual UDP sockets and peers may impose smaller limits. Native UDP
use is bounded to the supported local payload range through 32768 bytes.
When connecting to anytls-go v0.0.13 or sing-box v1.14.2, keep native-client UDP
payloads at or below 16384 bytes and peer-client payloads at or below 8192 bytes.
Larger responses can encounter peer short-buffer errors; these are conservative
compatibility ranges and do not describe each peer's exact maximum.

TCP compatibility includes IPv4/domain destinations, concurrent streams,
sequential session reuse, failed targets and negotiated v1 behavior. The
anytls-go example CLI has no certificate/CA flags and uses insecure defaults;
configure certificate validation explicitly when choosing a peer client.

## URI and exports

`anytls://password@host[:port]/?sni=name&insecure=0|1#display-name` is imported and
exported through the common node URI path. Port defaults to 443. Passwords and
display names are percent encoded; IPv6 hosts use brackets. Verification is
secure by default and insecure mode must be explicit. URI export rejects custom
CA, ALPN and native options it cannot represent. Private keys and CA bytes are
never placed in the URI. Native profiles also export to sing-box v1.14.2; custom
native limits, multiplex controls and version overrides are rejected if they
cannot be represented. sing-box JSON import is not currently offered for AnyTLS.

## Bounds and lifecycle

The server accepts at most 512 TLS sessions and 128 active streams per session.
Inbound queues are bounded to 4 MiB per stream and 16 MiB per session. Excess
queued data closes the affected stream; invalid session commands close the
session. Settings/update payloads are at most 8192 bytes, alerts/open errors at
most 1024 bytes, and data frames at most 65535 bytes. Socket writes and destination
opens default to 5 seconds. Read deadlines are stream-local. A write deadline
interrupts that stream's active socket write; a partial protocol write failure
closes the session because its framing cannot safely resume.

Closing a client cancels pending dials and joins its sessions and idle worker.
Closing a server closes listener/sockets and joins session/proxy workers. The
implementation is experimental. Real-world server/hardware deployment is not
yet qualified. Linux arm64 is BUILD ONLY.
