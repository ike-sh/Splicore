# Native NaiveProxy

Splicore implements NaiveProxy protocol compatibility using its native networking
stack. Client and server support TLS HTTP/2 CONNECT and QUIC HTTP/3 CONNECT,
Basic proxy authentication, TCP destinations, Naive payload padding, padding
negotiation and concurrent streams. Compatibility is qualified locally with
official NaiveProxy `v154.0.8037.49-4` and Caddy forwardproxy `v2.11.7-naive`.

The protocol key is `naive / connect / base`, under engine `native`. Naive is a
first-class proxy protocol. Its carriers are specific to this protocol; XHTTP
HTTP/3 and generic V2Ray QUIC transport remain **not implemented**.

Chromium TLS/HTTP fingerprints, HPACK/QPACK encoding and scheduling, RST_STREAM
traffic shaping, and client preamble fingerprint parity are **not claimed**.
Splicore requires no Chromium, Cronet or external proxy process.

## Server

Use the managed creation API with protocol `naive`, for example
`POST /api/v1/creation/naive/plan`, followed by the shared apply operation:

```json
{
  "schema": 1,
  "name": "Naive server",
  "listener": {"host": "127.0.0.1", "port": 8443},
  "display_endpoint": {"host": "proxy.example", "port": 8443},
  "settings": {
    "mode": "https",
    "tls": {
      "server_name": "proxy.example",
      "certificate_file": "/etc/splicore/cert.pem",
      "private_key_file": "/etc/splicore/key.pem",
      "ca_certificate": "<one PEM CA certificate>"
    },
    "max_streams": 512,
    "connect_timeout": "5s",
    "idle_timeout": "10m"
  },
  "users": [
    {"account_name": "Alice", "username": "alice"},
    {"account_name": "Bob", "username": "bob", "password": "replace-with-a-strong-password"}
  ]
}
```

`mode: "https"` owns one TCP listener with TLS and ALPN `h2`.
`mode: "quic"` owns one UDP listener with TLS 1.3 and ALPN `h3`, requiring the
`with_quic` build tag. Offering both modes uses two explicit managed inbounds;
TCP and UDP can use the same numeric port.

The existing TLS service snapshots certificates and protected private keys.
Server settings require a DNS server name and one PEM CA certificate. Listener
and display endpoint remain separate. Unknown settings and explicit null option
values are rejected.

Creation accepts 1–16 users with distinct usernames. Omitted passwords are
generated by the shared credential service. Credentials use the existing
`username_password` kind; Account, Binding and Credential remain separate
records. Disabled accounts and bindings cannot authenticate. Credential rotation
and user changes restart the affected generation. Runtime counters attribute
authenticated payload bytes and sessions to each binding. Strict quota, speed
and session policies are unsupported; metadata-only policies are explicit.

`max_streams` is 1–512; omitted or zero selects 512. It bounds server CONNECT
admission across connections and each connection's stream limit. Missing or
incorrect authentication receives HTTP 407; malformed requests receive bounded
HTTP errors. Splicore makes no probe resistance claim.

Ordinary GET and HEAD requests receive a small static welcome response so the
current official client's preamble can complete. HEAD has no response body.
This surface does not serve files, delegate websites or reproduce a browser.

## Client

Create a canonical remote node with a separately owned credential. A node
creation mutation is:

```json
{
  "resource": "node",
  "action": "create",
  "node": {
    "name": "Naive endpoint",
    "protocol": {"protocol": "naive", "wire_version": "connect", "feature_profile": "base"},
    "endpoint": {"host": "proxy.example", "port": 443},
    "transport": {"kind": "tcp"},
    "security": {
      "kind": "tls",
      "tls": {"enabled": true, "server_name": "proxy.example", "trust": "system", "alpn": ["h2"]}
    },
    "options": {
      "schema_version": 1,
      "data": {"mode": "https", "padding": "auto"}
    },
    "metadata": {}
  },
  "credential": {
    "kind": "username_password",
    "value": "{\"username\":\"alice\",\"password\":\"replace-with-a-strong-password\"}"
  }
}
```

Use the existing client plan/apply API, then create a native proxy outbound
referencing the node. For H3, set `options.data.mode` to `quic`, transport kind to
`quic`, and ALPN to `h3`. Here `quic` identifies the Naive carrier. Payload remains
**TCP only**. Native UDP forwarding, CONNECT-UDP, MASQUE and UDP-over-TCP extensions
are **not implemented**.

TLS verifies the server name and certificate chain. For private trust, use
`trust: "explicit_ca"` and `ca_certificate` with one PEM CA certificate. There is
no insecure verification switch. ALPN can be omitted, or must be exactly `h2`
for HTTPS and `h3` for QUIC. Domain, IPv4 and IPv6 TCP targets are supported.

Client `options.data`:

| Field | Default | Meaning |
| --- | --- | --- |
| `mode` | Required | `https` or `quic` |
| `padding` | `auto` | Negotiate padding; `enabled` requires support; `off` uses raw payload |
| `extra_headers` | Empty | Up to 32 distinct non-reserved headers, 8192 total name/value bytes |
| `max_connections` | `1` | 1–4 connections admitting new streams; zero selects the default |
| `max_streams` | `128` | 1–512 total concurrent CONNECTs, including pending and retired streams |
| `connect_timeout` | `5s` | Bounded connection establishment and CONNECT negotiation |
| `tunnel_timeout` | `30m` | Retire an underlying connection from new CONNECT admission |
| `idle_timeout` | `10m` | Close idle streams and unused connections |
| `congestion_control` | Empty | H3 uses CUBIC; only explicit `cubic` is accepted in QUIC mode |

Durations accept Go duration strings from 1 second to 24 hours. Unsupported flow
control fields and algorithms are rejected. H3 receive windows are fixed and
bounded: stream initial/max 1/8 MiB, connection initial/max 4/32 MiB. These are
native stack settings without a Chromium tuning parity claim. QUIC datagrams and
0-RTT are disabled.

Extra header names and values reject CR/LF, invalid tokens, duplicate names with
different casing and transport-owned overrides. Reserved headers include
Proxy-Authorization, Proxy-Authenticate, Padding, Padding-Type-Request,
Padding-Type-Reply, Fastopen, Host, Content-Length, Transfer-Encoding, Connection,
Proxy-Connection, Upgrade, Keep-Alive, TE, Trailer and Accept-Encoding.

## Padding and stream lifecycle

The published Naive record format uses a big-endian 16-bit payload length, an
8-bit padding length, the payload and padding bytes. The first eight records in
each direction of each CONNECT stream are padded independently. Payload chunks
are at most 65535 bytes; larger writes split, then switch to raw bytes after the
eighth record. Padding lengths are uniformly random from 0 to 255. Splicore
writes zero padding and accepts arbitrary received padding bytes.

The Padding header's presence signals support. Requests use a random 16–32
character value and responses 30–62. A regular CONNECT peer without that header
uses raw payload. The client waits for the CONNECT response before sending
payload; Fast Open is not implemented. Header compression and HTTP frame shape
parity are not claimed.

Streams share bounded HTTP connections while retaining independent padding,
deadlines, destination and cancellation. Closing a stream preserves unrelated
streams. At `tunnel_timeout`, a connection stops accepting new streams; existing
streams remain usable and close after being idle for `idle_timeout / 10`.
Retired connections remain alive while their existing streams drain and do not
count toward `max_connections`. The total `max_streams` limit includes streams
on those retired connections. Each retired connection closes when its streams
finish. H2 response bytes are flushed while upload continues; its response
END_STREAM is sent when both directions complete and the handler returns. H3
streams can finish their sending direction independently. Shutdown joins owned
workers and closes TCP/UDP listeners and sessions. Application deadlines belong
to their CONNECT stream, without changing shared connection deadlines.

## Import and export

URI import/export supports the established bounded forms:

```text
naive+https://username:password@proxy.example:443#Display%20name
naive+quic://username:password@[2001:db8::1]:443#Display%20name
```

Usernames, passwords and fragments are percent encoded; omitted ports default to
443. Paths and query options are rejected. URIs carry endpoint, credentials and
display name with system TLS trust and default options. URI export rejects
custom CAs, distinct server names and richer options to prevent silent loss.
Use canonical configuration for those settings. URI export follows the existing
explicit secret-export policy. External client JSON formats are unsupported.

Linux arm64 remains **build only**. Real hardware is **not yet qualified**;
localhost protocol compatibility does not certify deployment or browser identity.
